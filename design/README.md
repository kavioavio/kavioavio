# Design source

The profile headers follow the Zidos design system. Nothing in `assets/` or
`zidos-dev/profile/assets/` is edited by hand; it is generated by `build.py`.

| File | Source in `zidos-core` (commit `60d36ab`) |
|---|---|
| `tokens.json` | `app/design-export/tokens.json`, the colour roles used here, light and dark |
| `fonts/Onest-subset.ttf` | `app/design-export/fonts/`, SIL OFL 1.1, see `fonts/OFL-Onest.txt` |
| `fonts/JetBrainsMono-subset.ttf` | `app/design-export/fonts/`, SIL OFL 1.1, see `fonts/OFL-JetBrainsMono.txt` |
| `done.svg` | `app/design-export/icons/set-b/done.svg`, drawn inline by `build.py` |

How the headers apply it:

- The header is a module tile (`--module`) with a directional hairline: sides
  and bottom, no top edge.
- In the light pole a raised object gets one shadow layer (`--shadow-lift`). In
  the dark pole there are no shadows; lift is a light top edge (`--edge-lift`).
- Status colours carry status only: `--awaiting` marks the unverified
  `finish.claimed`, `--ok` the verified `run.succeeded`. The accent appears
  once, on the product name.
- Type: Onest for words, JetBrains Mono for identifiers and log lines.

Rebuild:

```sh
pip install fonttools brotli
python3 design/build.py
```

The build is deterministic: running it twice yields identical files. Fonts are
subset to the characters each header uses and embedded, because GitHub renders
README images as `<img>`, which cannot load external fonts.
